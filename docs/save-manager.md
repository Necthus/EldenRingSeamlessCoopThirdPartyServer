# 启动器存档管理（试用版，2026-10-25）

启动器的「存档管理」页使用 Windows 原生控件；不安装额外程序，不运行 Python、BAT 或 PowerShell。所有读取、转换、备份与恢复逻辑都嵌入 `ersc_launcher.exe`。Python 和 C# 测试程序只用于开发验证。

## 操作

1. 完全退出游戏，打开 `ersc_launcher.exe`，切换到「存档管理」。
2. 左侧选择源 SteamID、存档类型（原版 `.sl2` 或无缝 `.co2`），再选择角色。列表显示槽位、名字、等级、游戏时长。也可以用「浏览」选择其他位置的文件。
3. 右侧选择目标 SteamID、类型和目标槽位。两侧的 SteamID 可以不同，也支持同类型跨账号复制。目标 SteamID 可以手动输入新 ID；该操作不会更改「启动与联机」中的游戏身份。
4. 点击「检查道具」可查看源角色中当前规则识别到的无缝专用物品。
5. 点击「转换 →」查看预览：源／目标 SteamID、角色槽、目标文件、将清理的物品。确认后自动备份并写入；选到已有角色的目标槽时，预览会明确显示被覆盖的角色名。
6. 「导出副本」允许另选输出路径，不必直接写入正在使用的账号目录。目标文件已存在时，仍按右侧选择的目标槽位导入并保留其他角色；账号或版本不匹配会拒绝写入。

默认路径为使用者自己的 `%APPDATA%\EldenRing\<完整SteamID64>\ER0000.sl2` 或 `ER0000.co2`。源账号文件保持原样。目标文件不存在时，使用源文件的容器与公共数据建立仅含所选角色的存档；其他角色槽清空。已有目标则保留目标公共数据、其他角色和 regulation 区段，只更新目标角色槽、摘要、活动状态及相应校验值。

转换完成后，用对应模式及目标 SteamID 进入游戏测试。自建服务器模式中的 SteamID 来自 `steam_settings/configs.user.ini`；Steam 模式使用真实 Steam 身份。管理页不会替你切换游戏身份或网络接口。

## 隐式备份与恢复

每次转换均自动保存源文件、目标文件及两者已有的 `.bak`，位置为：

```text
%APPDATA%\EldenRing\SeamlessLauncherBackups\<日期-时间-随机后缀>\
```

文件使用 `source-ER0000.co2`、`target-ER0000.sl2` 等易于辨认的名字。`operation.json` 记录原路径、源／目标 SteamID、角色槽、转换方向、SHA-256、清理列表和操作结果；原本不存在的文件也会记录。备份不会自动轮换或删除。

- 「打开备份目录」：查看所有备份。
- 「备份目标」：手动备份右侧选中的存档与其 `.bak`。
- 「恢复备份」：进入某次备份目录，选 `operation.json`。恢复前再次自动备份当前目标，然后恢复那次操作之前的目标主文件及 `.bak`；不回退源账号的进度。原目标不存在时，恢复会移除转换时新建的目标文件，而当前文件已在恢复前备份。

转换会先验证源、目标文件及所有 12 个 MD5 区段。预览后文件有变化、游戏仍在运行、备份失败或发现不支持的布局时拒绝写入。主文件和 `.bak` 各自原子替换，写入失败尝试回滚；电脑在两次替换之间断电等情形可从备份目录恢复。

## 自动道具识别的范围

当前规则识别 Seamless Co-op 的 12 类道具，Goods ID 为 `8380001–8380012`：袖珍大壶、玛莲妮亚雕像、挑战者之针、离别迷雾、判官法典、卢恩之酒、五类腐败精华、干缩手指。

转换到原版时，按结构读取背包与仓库的普通／重要物品区，清除匹配的条目及数量为 0 的残留记录，调整相应条目计数，并移除快捷栏、随身包和装备镜像中的对应引用。角色账号绑定同时更新为目标 SteamID；不会直接对整个文件做无差别数值替换。转换到无缝时保留物品，由 Mod 在实际运行时处理其联机道具。

这是明确的 ID 规则，不是自动推断任意 Mod 新增的全部道具。遇到 `8380000–8389999` 保留区中不在规则内的物品会阻止转原版，不猜测删除。其他 Mod 的不同 ID、额外状态效果及自定义事件尚无通用识别能力。普通物品、DLC 物品和任务标记保留；不会推测、补齐或合并 Boss／任务进度。

## 支持与验证

浏览支持已验证的 PC BND4 固定容器；转换暂限定全局与源角色内部格式值 `261`。这个值不是游戏版本号。已有目标的全局格式值必须一致；不提供跨版本降级。

已用本机真实原版／无缝存档及 `ame` 原存档作为只读输入，在临时目录验证：两方向、跨账号、新建目标、其他角色保留、全部普通／DLC 物品条目保留、已知道具清理、未知保留区道具拦截、校验损坏拒绝、预览过期拒绝、自动备份和逐字节恢复。测试不改写本机真实存档，不加载角色。旧版启动器的配置／DLL 备份恢复测试与高 DPI 布局测试也已运行。

输出通过文件校验不等于游戏内加载已通过。本功能当前为试用，需由使用者实际加载、正常退出再确认。之前 `ame` 跨账号存档的加载失败原因仍未定位，本功能不把该问题视为已经修复。
