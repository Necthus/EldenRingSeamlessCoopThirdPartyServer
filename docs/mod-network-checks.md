# 禁止 Mod 启动联网检查

2026-10-31 为当前 Seamless Co-op 2.0.1 增加进程范围的联网检查开关。无需安装软件、管理员权限或外部脚本；逻辑随 `ersc_launcher.exe` 一起分发。

## 使用

在「启动与联机」页勾选「禁止 Mod 启动联网检查」，然后正常点击「启动游戏」。默认开启，Steam／自建服务器两种模式都可以选择。选项自动保存至 `SeamlessCoop/ersc_settings.ini`：

```ini
[NETWORK]
block_mod_update_checks = 1
```

`1` 表示启用拦截；`0` 表示关闭并恢复原有启动路径。未填写时默认开启。变更在下一次由新启动器启动游戏时生效，不会改变正在运行的游戏。直接运行 `ersc_launcher.original.exe` 或从其他入口注入 Mod 不经过这个开关。

## 实际拦截范围

本机启动诊断捕获到游戏初始化阶段连续三次 `CONNECT raw.githubusercontent.com:443` 请求；让这些请求在本机快速失败后，游戏仍创建窗口、加载 `ersc.dll`。当前实现阻止游戏进程通过 libcurl HTTP 代理机制发往精确主机名 `raw.githubusercontent.com` 的 HTTP/HTTPS 请求，在 DNS 查询、建立远程连接或 TLS 之前返回本地 HTTP 503。没有伪造“已经是最新版”的成功响应，也没有解密 HTTPS。

这是目标主机级别的拦截，不仅是隐藏提示。它会同时阻止 Mod 从此主机读取的其他检查（例如若同域名还提供版本之外的信息）；不宣称只识别某个 URL 路径。未来 Mod 更换检查域名或不再遵循代理设置时，需要重新验证。

不会修改 `ersc.dll`、Steam 接口 DLL、系统代理、系统防火墙、hosts、Cloudflare 或 WireGuard 设置。Steam/GSE/WireGuard 原有的联机数据传输不经这个 HTTP 守卫。其他 HTTP 主机通过守卫继续连接；若启动环境原本配置 HTTP/HTTPS 上游代理，守卫为允许的主机保留该上游，并尊重原有 `no_proxy`。原有 SOCKS 等尚未支持的上游代理会提示错误，不会静默丢弃；可取消勾选恢复原启动方式。

## 后台进程与日志

启用时，启动器启动一个自身的无窗口守卫，再通过原 Mod 启动器启动游戏。代理仅监听随机的本机 IPv4 回环端口，需要本次随机凭据，不对局域网或公网开放。代理环境变量只传给这次启动的原启动器及其游戏子进程，系统和其他软件不受影响。无窗口守卫在游戏退出时自动结束；启动失败、90 秒内未找到本次游戏时也会退出。

因此，游戏运行期间任务管理器中可能有一个资源占用很低、没有窗口的 `ersc_launcher.exe`，这是正常的联网检查守卫。不要在游戏运行时手动结束它，否则该游戏剩余的代理型 HTTP 请求会失败。取消开关并重新启动游戏后，不再创建守卫。

日志位置：

```text
%LOCALAPPDATA%\SeamlessCoopLauncher\NetworkLogs\
```

日志记录被拦截／放行的主机、时间和游戏进程生命周期；不记录代理凭据、请求头、URL 路径、查询参数或存档内容。`blocked host=raw.githubusercontent.com` 表示该请求已在本机被阻止。守卫启动失败会在启动器显示错误，不会默默按未拦截模式继续。

## 验证范围

- 本机初始诊断：三次启动 HTTP CONNECT 请求均在本机返回失败，游戏创建窗口并加载原 `ersc.dll` 与 GSE 接口。
- 更新后的成品守卫实测：三次 `raw.githubusercontent.com:443` CONNECT 请求均记录为 `blocked`，没有转发；游戏窗口标题为 `ELDEN RING™`，进程正常响应，已加载原 `ersc.dll` 与 GSE 接口。本机 `.sl2`、`.co2` 及各自 `.bak`、核心 DLL 与根目录 Steam 接口 SHA-256 均保持不变。未操作角色进入世界。
- 回环网络测试：HTTP/HTTPS 目标拦截、大小写／尾点、拒绝未认证请求、允许目标的透明 TCP 隧道及 HTTP 转发、原有上游代理及其认证、`no_proxy`、环境变量进程隔离、敏感信息不写日志、守卫随模拟游戏退出，共 43 项检查通过。
- 在同样的代理环境下运行原 GSE 双进程测试：搜房、入房、握手、可靠／不可靠消息、64 KiB 消息和旧 P2P 接口通过；这些数据没有进入 HTTP 守卫。测试不加载真实游戏或 Mod，也不等于多人游戏内联机验证。
- 原启动器配置／接口备份恢复回归 70 项，高 DPI 布局 399 项检查通过。

当前针对工作区既有的 2.0.1 核心与配套 GSE 接口验证。原 DLL 文件哈希保持不变。本功能不处理原游戏／Mod 的其他初始化等待，也不保证消除所有无窗口启动问题。
